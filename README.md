# Perfect Consign

This is the product copy of the Stall baseline at `27e5e88a740e676024268fdf2ebf2e09ba3bad87`. Stall stays the baseline and is not edited from this tree.

No hacks, no shortcuts, no workarounds, and no patches. Fix the design that is wrong. Do not leave a second calculation in application code, or nudge a date or flag so that calculation happens to match the database. Money and balances come from the view or function that owns them.

## Database

PHP `8.5`. Postgres `18.6`. Host port **5436**. Database `consign`. User `stall`. Volume `perfect_consign_pg`. Container `perfect-consign-postgres`. Do not use ports 5432, 5433, 5434, or 5435, and do not use volume `stall_pg`.

`stall_poster` inserts journals and lines. It cannot turn triggers off, drop them, or set replica mode. Append-only triggers fire in replica mode too, so that session still cannot update, delete, or truncate them.

## Threat model

The boundary is `stall_poster` and `stall_app`. A superuser can `DROP EVENT TRIGGER` or set `event_triggers=false`. Postgres does not deliver those statements to an event trigger. That is outside the product role.

## Load

`php bin/provision-platform.php` is the fresh install. The numbered migrators are two installers only: `sql/000_platform.sql` (platform + admin + cluster roles such as `stall_vendor_entry`, mail, wipe helpers) and `sql/001_tenant.sql` (full mall schema). `SchemaCatalog::PLATFORM_AFTER` is empty. `000` creates `stall_app`, `stall_backup`, `stall_worker`, `stall_vendor`, the platform tables, schema `extensions`, and `btree_gist`. A second platform run exits 0 and does not re-apply. After `platform_reject_guard_function_replace` exists, replacing `platform.reject_append_only_trigger_change` is refused. Then provision a mall: `001` is rewritten from `public` into the mall schema. An existing database is not upgraded across installer edits: `MigrationFileChanged` means wipe + reprovision (or, later, a new forward `0NN_*.sql`). There is no forget/refresh checksum CLI. To empty a disposable DB: `STALL_ALLOW_PLATFORM_REINSTALL=true` (that flag alone is the wipe gate — demo hosts may still use `APP_ENV=production` for the route cache) and `php bin/reinstall-empty-database.php`, then `provision-platform` and `seed-mall`. `bin/deploy-demo.sh` runs `git clean -fd -- sql/` after `git reset --hard` so untracked leftover migrations under `sql/` are removed without deleting host-only files such as `composer.phar`. `php bin/work.php` claims due jobs once. `php bin/work.php --forever` keeps claiming them. `php bin/check-migration-freeze.php` allows the two-file baseline reset and otherwise refuses edits to stamped numbers. A tenant session path is `tenant_x, pg_catalog, extensions`. `public` is not a mall.

`STALL_DB_HOST`, `STALL_DB_PORT`, `STALL_DB_NAME`, `STALL_DB_USER`, and `STALL_DB_PASSWORD` are required. `STALL_APP_PASSWORD` is required for the web app (role `stall_app`). `STALL_PUBLIC_ORIGIN` is the canonical site origin (`https://example.com` or `http://127.0.0.1:8080`) used for password-reset and consignor magic links. The app refuses to start without it unless `STALL_ALLOW_HOST_ORIGIN=true` and `APP_ENV` is `local` / `development` / `dev` (or `APP_DEBUG=true` outside `production` / `prod`). Host-derived origin is never used in production-like env. `STALL_TRUSTED_PROXIES` is a comma-separated list of proxy IPs or IPv4 CIDRs; only those peers may supply `X-Forwarded-Proto` for Secure cookies and HSTS. If unset, forwarded proto is ignored. HSTS is `max-age=86400` without `includeSubDomains`. `PC_COVERAGE` is honored only when `APP_ENV` is `test` or `coverage`. Log and coverage directories are created as `0700`; rotate `var/log/app.log` with logrotate or an equivalent, or clear it from Admin → App log. `php bin/work.php` logs in as `stall_worker` with `STALL_WORKER_PASSWORD`. The site and the command scripts read `.env` (one parser: quotes, `export`, and inline `#` comments). A reset plants the Gmail mailbox from `STALL_GMAIL_ADDRESS`, `STALL_GMAIL_APP_PASSWORD`, and `STALL_MAIL_KEY`. `bin/deploy-demo.sh` writes `STALL_MAIL_KEY` into that file when the line is missing, then migrate seals any plaintext mailbox password with it.

```text
php bin/seed-mall.php
php bin/seed-dev-tenant.php
```

`php bin/seed-mall.php` removes slug `mall`, provisions it, loads `sql/mall_tenant.sql` (`operating_mode = booth_mall`, rentals on, consignment off), and posts a booth-mall rent demo (vendors, booths, open rent). It also rebuilds slug `shop` as consignment only (`sql/shop_tenant.sql` / `operating_mode = consignor`) with the consignment ShopDemo books. Sign in only at `/` with email + `STALL_OWNER_PASSWORD`: mall uses `STALL_OWNER_EMAIL`; shop plants `desk@cedar-consign.test` (or `STALL_SHOP_OWNER_EMAIL` when set). With `STALL_ALLOW_TENANT_RESET=1`, the owner header on `/dev`, `/mall`, and `/shop` shows Reset Test Data (type `RESET`) so that store alone can be wiped and reseeded on the local consign DB; a mall reset also rebuilds `shop`. After any local wipe of `mall` or `shop` (including `php bin/wipe-tenant.php mall|shop` and the end of `composer check`), run `php bin/ensure-demo-logins.php` so both stores exist again with those owner emails — it does not reload demo books; use `seed-mall` or Reset Test Data for that. The test suite still builds an empty `webprobe` when that slug is missing. Deploy (`bin/deploy-demo.sh`) migrates and plants passwords; it does not wipe or reseed books on a normal tip. When `000`/`001` bytes changed and `STALL_ALLOW_PLATFORM_REINSTALL=true`, deploy recreates an empty DB and provisions platform (mall/shop stay empty until seed). To reload https://v2.perfectconsign.com after an installer baseline change: set `STALL_ALLOW_PLATFORM_REINSTALL=true` on the host, push the tip, then run the `seed-demo` Action (`bin/seed-demo.sh` lands tip with `DEPLOY_SKIP_MIGRATE`, recreates the DB when that flag is set, provisions, then `seed-mall.php`).

`php bin/seed-dev-tenant.php` wipes slug `dev` and no other mall, provisions it, and loads `sql/dev_tenant.sql`: one vendor, one booth on Main Floor, one open assignment, and three items. It does not post a journal. The owner is still `php bin/set-owner.php dev owner` (optional `STALL_OWNER_EMAIL`).

## Application

`sql/000_platform.sql` creates the `stall_app`, `stall_backup`, `stall_worker`, and `stall_vendor` login roles, stores mall owners (username unique per mall; co-owners after `066_co_owners.sql`), and stores owner download times. The poster grants live in `sql/001_tenant.sql` and are applied inside each mall schema by the provisioner. `php bin/provision-platform.php` applies the platform file once.

The web app connects as `stall_app`. Set `STALL_APP_PASSWORD`, `STALL_BACKUP_PASSWORD`, and `STALL_WORKER_PASSWORD` in the environment or in `.env`. That file stays out of git. `STALL_PG_DUMP` is `pg_dump` on `PATH`, a path to the Postgres 18 client, or `docker:perfect-consign-postgres` to use the client in that container. The host client must be 18. A Postgres 17 client cannot dump this server.

```text
php bin/enable-stall-app.php
php bin/set-owner.php mall owner
```

`set-owner.php` reads `STALL_OWNER_PASSWORD` and optional `STALL_OWNER_EMAIL`. The same `STALL_DB_*` values used for provisioning are required. A duplicate sign-in email across malls is refused. When the password already matches, username/email can update without bumping `credentials_version` (active sessions stay valid). The site is `public/index.php` with DocumentRoot = `public/` (repo-root `.htaccess` denies `.env`, `.github/`, `composer.phar` / `*.phar`, and other application paths if misconfigured). Sign-in is only at `/` (email + password). Bare `/{slug}` and old `/{slug}/login` / `/{slug}/forgot` bookmarks redirect to `/` or `/forgot` (or the signed-in role home). Five failed email sign-ins from one address in fifteen minutes lock that pair; forty failures from one address across any emails lock the address; twenty failures for the same email from any addresses lock the email. Stale failure rows are pruned on the next failure. Every response sends an enforcing Content-Security-Policy (`script-src` / `style-src 'self'`, no `unsafe-inline`); page scripts and styles are files under `/assets/`. Edge helpers and TLS/origin/CSP rules are documented in `docs/http-edge.md`. `bin/deploy-demo.sh` runs `composer build:routes` after install so `var/cache/feature-controllers.php` matches the tree on the demo host; other production hosts must do the same. Email sign-in lockout (pair, address spray, email-wide) lives in `sql/000_platform.sql`.

Platform admin is `/admin`. After `php bin/migrate.php platform`, run `php bin/set-platform-admin.php` with `STALL_PLATFORM_ADMIN_EMAIL` and `STALL_PLATFORM_ADMIN_PASSWORD` set. When the password already matches, the script leaves `credentials_version` alone (active admin sessions stay valid). Admin forgot-password and signup confirmation send in the web request through `STALL_GMAIL_*` or `STALL_SMTP_*` (not the mall Settings mailbox). `bin/deploy-demo.sh` plants the platform admin from those env vars the same way it plants the mall owner. The slug `admin` is reserved and cannot be provisioned as a store. Admin → Mail worker shows whether `STALL_WORKER_PASSWORD` is set, the last `php bin/work.php` run, waiting outbox mail, and a prune/clear run log. Mall password resets and receipt emails send in the web request through Settings; other store mail waits for the worker. `php bin/migrate.php platform-after` is a no-op on the two-installer baseline (`PLATFORM_AFTER` is empty; those objects live in `000`).

```bash
php -S 127.0.0.1:8096 -t public public/index.php
```

That demo server is HTTP. Secure cookies and HSTS stay off unless the process sees trusted TLS (`HTTPS` or a peer in `STALL_TRUSTED_PROXIES`). Self-serve `/signup`, promo codes, and the military customer tax path are not in this tree yet.

## Tests

`composer test` runs the unit suite. `composer test:integration` runs the tests that open Postgres. `composer test:http` runs the HTTP suite (excludes the mutating surface form crawl). `composer check` runs those suites plus PHPStan, PHPMD, and the proofs. A green `check` on `master` is what deploys the demo. `composer test:mutate` and `composer test:coverage` run on a nightly GitHub Action; coverage does not block deploy. `test:coverage` sets `APP_ENV=coverage` and runs unit/integration then http as separate PHPUnit processes under Xdebug so ProbeServer HTTP dumps collect under `PC_COVERAGE` without a one-process hang (see `docs/http-edge.md`). `composer test:smoke` and `composer test:http` boot the site on `127.0.0.1:8097` and drive it over HTTP. Smoke includes the GET surface link crawl for every mall role (and owner preview `?as=`). `composer test:surface-mutate` submits safe forms on that same graph; `composer test:browser` drives Chrome JS clicks (Print, preview Back). Both run on the `surface` GitHub workflow with Chrome and `sockets`. The browser suite needs the PHP `sockets` extension; `ChromeProbe` passes `noSandbox` and `--disable-dev-shm-usage` so Actions runners can start Chrome (override the binary with `CHROME_PATH`).

Codeception sits beside PHPUnit: `composer test:functional` (PhpBrowser) and `composer test:acceptance` (Chrome via chrome-php, no Chromedriver). `composer test:codeception` runs both after `codecept build`. Suites live under `tests/Codeception/` and boot mall `webprobe` on `127.0.0.1:8099`. They hit every static mall GET, crawl discoverable mall links and safe forms from role hubs, run explicit sale/rent/payout money paths, and Chrome-click every safe nav/btn/print control. Override with `WEB_BASE_URL` when pointing at an already-running probe. See `docs/codeception.md`.

Those commands use mall `webprobe` on the local database only — never `mall`, `shop`, or a pulled tenant. The suite creates `webprobe` when it is missing and sets its owner password. It posts journals into that mall. It does not change any other mall. If `STALL_DB_USER` and `STALL_DB_PASSWORD` are unset, the suite uses the local `docker-compose.yml` login.

## Proofs

Each fact `sql/prove_*.sql` rolls back. Run those proofs with `search_path` set to the mall schema from `platform.tenants`, then `pg_catalog`, then `extensions`. `php bin/prove-race.php` provisions slug `race`, then runs the two-session check, including the tenant slug and the on-hand sale. The `sql/prove_race_*.sql` files are not proofs on their own. `php bin/prove-tenant.php` rolls back the cross-tenant proof. `php bin/prove-backup.php` dumps a fixture mall and restores it into a second schema, then drops both.

An owner download is streamed and not kept. `php bin/backup-tenant.php <slug>` writes one zip per UTC day under `STALL_BACKUP_DIR`, which must be outside the `perfect_consign_pg` volume and outside the web tree (`public/` / DocumentRoot); tenant backup dirs are mode `0700`. Files older than 30 days are removed. `php bin/pull-tenant.php <slug>` copies one mall from `STALL_SOURCE_DB_*` onto local port 5436 database `consign` and refuses any other destination.

PC1 → PC2 **dev mirror** (not a cutover): `php bin/pc1-mirror.php refresh --target=local` read-only extracts Becca from prod, wipes disposable slug `beccas-mirror`, loads master data plus opening balances, and proves zero-cent drift. Never writes prod. v2 uses `--target=v2` with `STALL_MIRROR_V2_DB_*`. Details: [docs/pc1-mirror.md](docs/pc1-mirror.md).
